# TopMemo 設計書

## 1. 目的
- Windows 11 上で常駐し、指定ホットゾーンにマウスポインタが入ったら即表示される軽量メモ帳を提供する。
- Markdown テキストをタブ単位で管理し、色付けシンタックスハイライトとリンク遷移をサポートする。
- 設定・データはアプリフォルダに保存し、レジストリは使用しない。

## 2. 固定要件
- OS: Windows 11
- マルチモニタ: 対応
- 開発技術: C# / .NET 8 / WPF / AvalonEdit
- 二重起動:
  - 単一インスタンスで動作
  - 2重起動時は既存インスタンスを前面化し、新規プロセスは終了
- 表示/非表示:
  - ホットゾーンの位置・サイズは設定可能
  - 表示は侵入後即実行
  - エディタ領域からカーソルが外れたら即非表示
  - ホットゾーン重複時は `Win+Tab` 動作を優先
- タブ:
  - 初期タブは 1 つ
  - タブ右端の `+` ボタンで新規追加
  - タブ右クリックでタブ名変更
  - タブ右クリックでタブ削除
  - 最低 1 タブは常に維持（最後の 1 タブは削除不可）
  - タブ並び替えは初版で対応しない
  - タブ上マウスホイールで前後タブへ切り替え
  - タブ名は保存ファイル名として使用
  - ファイル名重複時は `name (2).md` 形式で連番回避
- 編集/保存:
  - テキスト変更時はメモリ更新のみ（dirty 管理）
  - 保存トリガーは「画面非表示時」「タブ切替時」「終了時」
  - 保存対象は dirty の全タブ
- ウィンドウ:
  - 最前面固定
  - タスクバー非表示
  - Alt+Tab 非表示
  - リサイズ可能
  - システムトレイ常駐
- システムトレイ:
  - 右クリックメニューに「表示/非表示」「自動起動」「終了」を表示
  - 「自動起動」はチェックマーク付きトグル
- Markdown:
  - プレビュー不要
  - 色付けによるシンタックスハイライト
  - リンククリックで遷移
  - リンク遷移の安全制限は設けない
- 追加アクション:
  - マウス左下ホットゾーン（位置変更可）で `Win+Tab` を送出
  - `Win+Tab` 再発火防止クールダウンは 300ms
- 自動起動:
  - 対応する
  - 実装はスタートアップフォルダ（`.lnk`）のみを使用
- 保存:
  - 設定・データはアプリフォルダ内で完結
- ログ:
  - `logs/app.log` は最大 100KB
  - 超過時は `logs/app.log.1` へローテーション（2世代保持）

## 3. 保存ファイル構成
アプリ実行ファイルと同じディレクトリに以下を配置する。

- `settings.json`: アプリ設定
- `tabs.json`: タブ順序・現在タブ・タブ名管理
- `memos/<tabFileName>.md`: タブ本文
- `logs/app.log`: 現在ログ
- `logs/app.log.1`: ローテーション済みログ

## 4. 設定仕様 (`settings.json`)
```json
{
  "hotZones": {
    "showEditor": {
      "x": 0,
      "y": 0,
      "width": 12,
      "height": 12
    },
    "sendTaskView": {
      "x": 0,
      "y": 1070,
      "width": 12,
      "height": 12
    }
  },
  "editorWindow": {
    "x": 20,
    "y": 20,
    "width": 720,
    "height": 480
  },
  "behavior": {
    "topMost": true,
    "autoStartEnabled": false,
    "taskViewCooldownMs": 300
  },
  "logging": {
    "maxFileSizeKb": 100,
    "rotateFileCount": 2
  },
  "theme": {
    "markdownColorProfile": "Default"
  }
}
```

## 4.1 タブ管理仕様 (`tabs.json`)
```json
{
  "activeTabId": "tab-1",
  "tabs": [
    {
      "id": "tab-1",
      "title": "memo",
      "fileName": "memo.md"
    }
  ]
}
```

## 4.2 設計方針
- 後方互換は持たない。
- マイグレーション処理は実装しない。
- `settings.json` / `tabs.json` が不正形式または必須項目欠落時は、デフォルト値で再生成する。
- タブ名変更時は保存ファイル名を同期変更する。
- 保存ファイル名に使えない文字は `_` に正規化する。
- 重複ファイル名は `name (2).md`, `name (3).md` の形式で解決する。

## 5. アーキテクチャ
### 5.1 構成
- `App`:
  - 起動、終了処理、サービス配線
- `SingleInstanceService`:
  - 単一インスタンス制御、既存インスタンス前面化通知
- `TrayService`:
  - 通知領域アイコン、右クリックメニュー（表示/非表示、自動起動、終了）
- `HotZoneMonitor`:
  - マウス位置監視、ホットゾーン侵入判定
- `HotCornerActionService`:
  - `Win+Tab` 入力送出
- `StartupRegistrationService`:
  - スタートアップフォルダ登録
- `EditorWindow`:
  - WPF ウィンドウ（AvalonEdit + タブ UI）
- `TabService`:
  - タブ追加、改名、削除、切替、保存先ファイル名管理
- `MarkdownHighlightService`:
  - AvalonEdit への Markdown 色付け定義適用
- `LinkNavigationService`:
  - カーソル位置のリンク判定、クリックで `Process.Start` 遷移
- `PersistenceService`:
  - `settings.json` / `tabs.json` / `memos/*.md` の読み書き
- `LoggingService`:
  - 100KB ローテーション付きファイルログ出力

### 5.2 技術選定理由
- WPF: 常駐アプリとの相性がよく、ウィンドウ制御が容易
- AvalonEdit: 軽量でシンタックスハイライト拡張が容易
- JSON 設定: ポータブル運用しやすい

## 6. 主要動作フロー
### 6.1 起動
1. `SingleInstanceService` で単一インスタンスを確保する。
2. 既存インスタンスがある場合は前面化を通知し、新規プロセスを終了する。
3. `settings.json` と `tabs.json` を読み込み（不正なら再生成）。
4. `tabs.json` に従い `memos/*.md` を読み込み（欠落時は空で作成）。
5. トレイアイコンとメニュー（自動起動チェック状態を含む）を生成する。
6. 非表示状態で `HotZoneMonitor` を開始する。

### 6.2 表示
1. `showEditor` ホットゾーンへ侵入。
2. 即時に `EditorWindow.Show()` を実行。
3. ウィンドウを最前面へ移動しフォーカス。

### 6.3 非表示
1. マウスがエディタウィンドウ境界外へ移動。
2. dirty の全タブを保存。
3. `EditorWindow.Hide()` を実行。

### 6.4 タブ操作
1. 初期表示時にタブ 1 件を表示。
2. `+` ボタン押下で新規タブ追加し、空ファイルを作成。
3. タブ右クリックメニューで「名前変更」「削除」を表示。
4. 名前変更確定で `title` と `fileName` を更新し、ファイル名を変更。
5. 削除時は対象ファイルとタブ定義を削除（ただし最後の 1 タブは削除不可）。
6. タブ領域でホイール操作時に前後タブへ切り替え。
7. タブ並び替えは初版で対応しない。

### 6.5 編集と保存
1. アクティブタブでテキスト変更イベント受信。
2. メモリ上データを更新し、対象タブを dirty にする。
3. 非表示時、タブ切替時、終了時に dirty の全タブを保存。
4. 保存失敗時はログ出力し、dirty 状態を維持して次トリガーで再試行。

### 6.6 `Win+Tab` 送出
1. `sendTaskView` ホットゾーンへ侵入。
2. クールダウン中でなければ `Win down -> Tab down/up -> Win up` を送出。
3. 送出後に 300ms のクールダウンを設定。

### 6.7 自動起動トグル
1. トレイメニューの「自動起動」をクリック。
2. メニューのチェック状態を切り替え。
3. 有効化時はスタートアップフォルダへの `.lnk` 作成を試行。
4. 無効化時は `.lnk` を解除。
5. 設定へ状態を保存。

## 7. マルチモニタ座標方針
- 監視座標系は `VirtualScreen` 基準（全ディスプレイ統合座標）を採用する。
- マイナス座標（左側/上側にあるモニタ）を許容する。
- ホットゾーンとウィンドウ座標は仮想座標で保存する。

## 8. ウィンドウ/トレイ制御方針
- `Topmost=true`
- `ShowInTaskbar=false`
- Alt+Tab 非表示のため `WS_EX_TOOLWINDOW` を付与
- リサイズ許可 (`ResizeMode=CanResize`)
- トレイから明示的に再表示可能
- トレイアイコン右クリックメニュー:
  - `表示/非表示`
  - `自動起動`（チェック付き）
  - `終了`

## 9. Markdown 表示仕様
- 対応要素:
  - 見出し
  - 強調
  - 箇条書き
  - コードブロック
  - インラインコード
  - リンク
- 非対応:
  - レンダリングプレビュー
  - 表示上の画像埋め込み
- リンク遷移:
  - クリックで OS 既定ブラウザへ遷移
  - スキーム制限は行わない

## 10. ログ仕様
- ログファイルは `logs/app.log` を使用する。
- ファイルサイズが 100KB を超えた時点でローテーションする。
- ローテーション時は既存 `logs/app.log.1` を上書きし、`logs/app.log` を `logs/app.log.1` へ移動後に新規 `logs/app.log` を作成する。
- ログ保持世代は 2（`app.log` と `app.log.1`）。

## 11. 例外時ポリシー
- 例外でアプリ全体を終了させず、ログ記録後に可能な限り継続する。
- 保存失敗時はメモリ上データと dirty 状態を保持し、次の保存トリガーで再保存する。
- 設定破損時はデフォルトへ戻し、ユーザー操作を継続可能にする。
- 自動起動登録に失敗した場合はトレイ通知し、アプリ本体は継続動作する。

## 12. 実装順序
1. WPF 基盤、単一インスタンス制御、トレイメニュー（表示/非表示、自動起動、終了）
2. ホットゾーン監視（表示/非表示 + `Win+Tab` 送出）
3. タブ UI（追加、改名、削除、ホイール切替）
4. AvalonEdit 組み込み、Markdown 色付け、リンク遷移
5. dirty 管理と保存トリガー（非表示、タブ切替、終了）
6. 自動起動登録（スタートアップフォルダ）
7. ログ出力と 100KB ローテーション
8. 設定 UI（2つのホットゾーン位置・サイズ、ウィンドウ位置、自動起動）
9. 長時間稼働確認
